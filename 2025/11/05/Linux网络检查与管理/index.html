Linux网络检查与管理

不同发行版管理网络的工具不完全一样。现代桌面和服务器常见 NetworkManager；有些服务器使用 systemd-networkd；旧系统可能还会看到 ifconfig、ifup、ifdown、dhclient。

先看网卡和地址

列出网卡接口

只看接口名称和状态也可以：

输出大概长这样：

接口名不一定是 eth0、wlan0。现代 Linux 常用可预测命名，例如 enp3s0、ens33、wlp2s0；虚拟机、容器和云主机也可能使用别的名称。

常见标志：

  • UP：接口被管理员启用。
  • LOWER_UP：底层链路可用，例如网线已连接或无线链路已建立。
  • BROADCAST：支持广播。
  • MULTICAST：支持组播。
  • LOOPBACK：回环接口，通常是 lo。
  • state DOWN 或 NO-CARRIER：接口未启用或没有检测到底层链路。具体含义要结合物理网卡、虚拟网卡和驱动状态判断。

UP 不等于“网络一定通”。它只说明接口处于启用状态；有没有 IP、路由和可达的对端还要继续检查。

这些字段可以这样理解：

  • 2:：内核中的接口索引，不是网卡名。
  • enp3s0：接口名称。
  • mtu 1500：最大传输单元，通常指一个 IP 包可承载的最大链路层负载大小；隧道、VPN 或特殊网络可能需要不同 MTU。
  • qdisc fq_codel：流量排队规则（queueing discipline）。
  • qlen 1000：发送队列长度信息。
  • link/ether：网卡的 MAC 地址。
  • brd：广播地址。以太网常见 MAC 广播地址是 ff:ff:ff:ff:ff:ff。
  • inet：IPv4 地址。
  • 192.168.1.23/24：地址和 CIDR 前缀长度；/24 对应常见子网掩码 255.255.255.0。
  • scope global：该地址属于全局作用域，不表示它一定能从公网访问。
  • dynamic：地址通常由动态配置获得，例如 DHCP；没有这个标记也不一定就代表手动设置。
  • valid_lft / preferred_lft：地址剩余有效时间和优选使用时间，forever 表示没有有限的到期时间。
  • inet6 ... scope link：IPv6 链路本地地址，只在本地链路范围内有效，通常以 fe80:: 开头。

接口只有 IPv6 的 fe80:: 地址、没有 IPv4 地址，可能是 DHCPv4 没成功，也可能是网络本来就只使用 IPv6。要看实际网络设计。

看路由、DNS 和连通性

查看路由表

常见 IPv4 路由可能是：

  • default：默认路由，目标地址没有匹配到更具体路由时使用。
  • via 192.168.1.1：下一跳网关。
  • dev enp3s0：从哪个接口发出。
  • src 192.168.1.23：这条路由常用的源地址。
  • metric：路由优先级数值，通常较小者优先（仍要结合策略路由等因素）。

一套简单的排查顺序

网络不通时可以按这个顺序走：

  1. ip -br link：接口是否存在、是否 UP。
  2. ip -br address：有没有合适的 IPv4 / IPv6 地址。
  3. ip route：有没有默认路由，网关是否正确。
  4. ping -c 4 <网关>：先测本地网关（注意 ICMP 可能被禁）。
  5. ping -c 4 1.1.1.1：区分外网 IP 连通问题和 DNS 问题。
  6. getent hosts example.com：检查系统 DNS 解析。
  7. sudo ss -lntup：服务是否监听在预期端口和地址上。
  8. sudo lsof -nP -i：进一步确认进程和 socket 的关联。

别上来就把网卡 down 掉，也别看到端口冲突就直接 kill -9。先搞清楚设备由谁管理、进程是什么、它为什么占着端口，后面就好办多了。
