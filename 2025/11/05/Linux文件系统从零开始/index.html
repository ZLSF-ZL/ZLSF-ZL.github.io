Linux文件系统从零开始

第一次接触 Linux 时，最容易让人迷路的不是命令，而是打开 / 之后这一堆目录。

/etc 里放什么？/var 为什么会越来越大？/proc 里面那些文件又是从哪来的？

我们从根目录开始，把常见目录和里面常见的文件过一遍。

先说明：Linux 发行版之间会有差异，软件安装方式和版本也会影响目录内容。下面介绍的是常见布局，不代表每台机器都一定有每个文件。

先认识文件系统

Linux 把文件、目录、设备等内容组织成一棵目录树，树的最顶端叫根目录，写作 /。

几个容易混淆的概念：

  • / 是根目录，是整个目录树的起点。
  • /root 是 root 用户的家目录。
  • /home/root 如果存在，也只是普通路径，和 /root 不是一回事。
  • ~ 通常表示当前用户的家目录；root 用户下通常展开为 /root。
  • Linux 中“目录也是文件”，设备也会以文件形式呈现，但它们的行为和普通文本文件不同。

/ 根目录

根目录下的目录不是随便起名的。Filesystem Hierarchy Standard（FHS）给出了常见的组织约定，不过现代发行版会有一些实现差别。

不是每个目录一定都单独占用一个磁盘分区。有些是普通目录，有些是挂载点，还有些是指向别处的符号链接。

/bin：基本用户命令

传统上，/bin 放系统启动和基本维护所需的常用命令，普通用户也经常会用到，例如：

  • ls：列出目录内容。
  • cp、mv、rm：复制、移动和删除。
  • cat、echo：输出文本内容。
  • sh：常见的命令解释器入口。

现代 Debian、Ubuntu 等系统常采用 合并 /usr（usr-merge） 布局：/bin 可能是指向 /usr/bin 的符号链接，而不是独立存放一套程序。

用 ls -ld /bin 可以查看它到底是目录还是链接。

/sbin：系统管理命令

传统上，/sbin 放系统管理、启动和修复相关的命令，例如文件系统检查、网络配置和系统启动工具。

常见的名字包括 fsck、ip、mkfs 等。不同发行版对这些命令的放置位置和普通用户是否能直接执行，处理方式并不完全相同。

在合并 /usr 的系统上，/sbin 也可能指向 /usr/sbin。

/lib、/lib64：基本共享库和内核模块

/lib 传统上存放 /bin、/sbin 中基本程序启动所需的共享库，以及部分内核模块。

常见内容包括：

  • 动态链接器，例如 64 位系统上的 ld-linux-x86-64.so.2（具体文件名依架构而定）。
  • C 标准库等共享库，常见文件名以 libc.so 开头。
  • 内核模块目录，例如 /lib/modules/<内核版本>/。

一些 64 位系统有 /lib64，用于放置或链接 64 位架构相关的库。usr-merge 布局也可能让 /lib、/lib64 成为指向 /usr 下目录的链接。

不要因为文件名看起来像普通文件就随手删除共享库。系统程序可能依赖它们，删错之后连常用命令都可能无法启动。

/etc：系统配置

/etc 主要放主机级配置文件。大部分内容是文本，适合用编辑器或 cat 查看；修改前要确认文件用途和权限。

常见配置文件

  • /etc/hostname：主机名。
  • /etc/hosts：本机维护的主机名与 IP 映射。
  • /etc/resolv.conf：DNS 解析器配置；在使用 NetworkManager、systemd-resolved 等服务时，它可能是自动生成的文件或符号链接，不一定适合直接长期修改。
  • /etc/fstab：系统启动时可能挂载的文件系统配置。
  • /etc/os-release：发行版名称和版本等信息。
  • /etc/passwd：用户账户的基本信息，例如用户名、UID、家目录和登录 shell。现代系统通常不在这里保存可直接使用的密码。
  • /etc/shadow：受限访问的账户口令散列及密码有效期信息。普通用户通常无权读取，不要把内容公开或随意改动。
  • /etc/group：用户组信息。
  • /etc/sudoers、/etc/sudoers.d/：sudo 授权规则。推荐使用 visudo 校验后修改，避免语法错误导致授权配置异常。
  • /etc/shells：系统认可的登录 shell 列表。
  • /etc/crontab：系统级定时任务配置之一。

常见配置目录

  • /etc/ssh/：SSH 服务端和客户端配置，例如 sshd_config、ssh_config。密钥文件通常位于 /etc/ssh/ 或用户的 ~/.ssh/，权限要求严格。
  • /etc/systemd/：systemd 的系统级配置和服务覆盖设置。
  • /etc/NetworkManager/：NetworkManager 配置（若系统使用该服务）。
  • /etc/apt/：Debian/Ubuntu 的软件源和 APT 配置。
  • /etc/yum.repos.d/、/etc/dnf/：部分 RPM 系发行版的软件仓库和包管理配置。
  • /etc/cron.d/、/etc/cron.daily/ 等：按计划执行的系统任务配置。

这里有个实用原则：/etc 通常放配置，不是程序本体，也不是系统日志仓库。一个软件可能在 /usr/bin/ 放可执行文件，在 /etc/ 放配置，在 /var/ 放运行数据。

/home：普通用户的家目录

普通用户的个人文件通常放在 /home/<用户名>/，例如：

以点开头的文件或目录通常是隐藏项，ls -a 才会显示。

常见配置文件包括：

  • ~/.bashrc：交互式 Bash shell 常用配置。
  • ~/.profile：登录 shell 环境配置之一。
  • ~/.ssh/config：SSH 客户端配置。
  • ~/.ssh/authorized_keys：允许登录此账户的公钥列表。
  • ~/.gitconfig：Git 用户级配置。

每个用户能读写哪些文件由权限控制。比如 SSH 私钥 ~/.ssh/id_ed25519 应当限制为仅所有者可读写；公钥 id_ed25519.pub 则不是秘密。

/root：root 用户的家目录

/root 是超级用户 root 的家目录，作用上类似普通用户的 /home/<用户名>，但它不在 /home 里面。

这里可能有 root 自己的 shell 配置、脚本、下载文件和 SSH 配置。它通常受到权限保护，普通用户不应默认能够访问。

注意：切换到 root 并不会让 /root 变成根目录。路径 / 才是目录树的根。

/usr：大部分用户空间程序和只读数据

/usr 历史上表示 Unix System Resources。它通常包含系统安装的软件、库、文档和共享资源；不是普通用户的家目录。

常见子目录：

  • /usr/bin/：大部分用户命令和应用程序，例如 python3、git、less。
  • /usr/sbin/：系统管理类程序。
  • /usr/lib/：程序使用的共享库、插件和其他支持文件。
  • /usr/share/：与架构关系较小的共享数据，例如 man 手册、locale 数据、图标和文档。
  • /usr/include/：C/C++ 等开发用头文件。
  • /usr/src/：部分软件或内核的源代码。
  • /usr/local/：管理员手动安装的软件和本地数据，常见结构包括 bin/、sbin/、lib/、share/。

例如，包管理器安装的 git 可能位于 /usr/bin/git；管理员自行安装的软件则可能放在 /usr/local/bin/。

/usr 的名字容易让人误会成用户目录。普通用户个人文件主要看 /home，root 的个人文件主要看 /root。

/var：经常变化的数据

/var 存放运行过程中会变化的数据。日志、缓存、队列和应用状态都可能在这里，因此它也经常是磁盘空间告急的来源。

常见子目录和文件：

  • /var/log/：日志目录，例如 syslog、auth.log（Debian/Ubuntu 常见），或 messages、secure（部分 RPM 系发行版常见）。具体日志由发行版和日志服务决定；systemd 系统还可能用 journalctl 查看 journal。
  • /var/cache/：可重新生成的缓存，例如包管理器缓存。
  • /var/lib/：应用程序的持久状态数据，例如包管理器数据库、服务状态和容器数据。
  • /var/spool/：等待处理的队列数据，例如打印任务或邮件队列。
  • /var/tmp/：临时文件，但通常比 /tmp 更适合需要跨重启保留的临时数据；是否保留仍取决于系统策略。
  • /var/backups/：部分发行版或软件保存的备份文件。
  • /var/www/：常见 Web 服务器站点目录之一，但不保证每个系统都有，也不一定是实际站点根目录。

日志轮转后可能出现 .1、.gz 等文件。看日志时先确认文件名和服务，别直接把整个目录打包上传，里面可能包含账户、请求或网络信息。

/tmp：临时文件

/tmp 用于存放临时文件。程序可能在这里创建 socket、缓存和中间文件，系统通常允许多个用户创建文件，所以权限和文件名处理都很重要。

常见系统会在重启时清理 /tmp，但清理时机和策略由发行版配置决定，不能把它当作可靠的长期存储位置。

/var/tmp 也存放临时数据，通常用于期望保存得更久的临时文件。程序具体使用哪个目录由自身实现和环境变量决定。

/dev：设备文件

/dev 中的条目代表设备或由内核提供的特殊接口。它们不是普通文件，读写它们可能会直接与设备或内核功能交互。

常见条目：

  • /dev/null：丢弃写入的数据；读取时立即得到文件结束。
  • /dev/zero：读取时产生零字节。
  • /dev/urandom：提供随机字节。
  • /dev/tty：当前终端设备。
  • /dev/console：系统控制台。
  • /dev/sda、/dev/nvme0n1：磁盘设备示例，名称依硬件和系统而异。
  • /dev/pts/：伪终端设备目录，常见于终端模拟器和 SSH 会话。

现代系统通常通过 udev 等机制动态管理设备节点。不要把磁盘设备当普通文件乱写：写错设备可能破坏分区或数据。

/proc：进程和内核信息的虚拟文件系统

/proc 通常不是磁盘上的普通目录，而是内核动态提供的 procfs。读取其中的条目，就像通过文件接口查看进程和内核信息。

常见条目：

  • /proc/cpuinfo：处理器信息。
  • /proc/meminfo：内存统计信息。
  • /proc/uptime：系统运行时间和空闲时间。
  • /proc/mounts：当前挂载信息之一。
  • /proc/cmdline：内核启动参数。
  • /proc/<PID>/：某个进程的信息目录；PID 是进程号。
  • /proc/self/：当前访问进程对应的目录链接。
  • /proc/<PID>/cmdline：进程启动参数。
  • /proc/<PID>/fd/：进程打开的文件描述符链接。
  • /proc/<PID>/status：进程状态和资源信息。

某些 /proc/sys/ 下的项目可用于查看或调整内核参数；是否可写取决于具体项目、权限和系统配置。别因为它“看起来像文件”就随意写值。

/sys：设备、驱动和内核对象

/sys 通常是内核提供的 sysfs，用于呈现设备、驱动、总线和内核对象之间的关系。

常见位置包括：

  • /sys/class/：按设备类别组织的信息，例如网络接口、电源设备。
  • /sys/block/：块设备信息。
  • /sys/devices/：设备层级结构。
  • /sys/firmware/：固件相关信息（内容取决于硬件和内核）。

其中有些属性是可读写的，写入可能改变设备或内核行为。了解具体接口前不要直接修改。

简单区分：/proc 更常用于进程和内核运行信息，/sys 更常呈现设备模型和内核对象；两者都不是普通磁盘数据目录。

/run：本次启动期间的运行时数据

/run 用于保存系统运行时状态，例如 PID 文件、服务 socket 和锁文件。它通常由临时文件系统挂载，重启后内容会重新建立。

常见例子：

  • /run/lock/：运行时锁文件。
  • /run/user/<UID>/：某个用户会话的运行时文件。
  • /run/systemd/：systemd 运行状态相关数据。

旧系统中部分运行时文件会放在 /var/run，现代布局里 /var/run 常是指向 /run 的链接。

/boot：启动所需文件

/boot 存放引导程序和 Linux 内核启动相关文件。常见内容有：

  • vmlinuz-<版本>：压缩的 Linux 内核映像。
  • initrd.img-<版本> 或 initramfs-<版本>：初始内存文件系统映像，用于启动早期加载驱动和工具。
  • System.map-<版本>：内核符号地址信息文件，是否安装取决于发行版和软件包。
  • grub/：GRUB 引导程序配置和相关文件（使用 GRUB 的系统常见）。

有些机器会把 EFI 系统分区挂载在 /boot/efi。这不是所有 Linux 安装都相同。

不要随手删除旧内核或修改引导配置。系统可能仍依赖这些文件启动，清理时优先使用发行版提供的包管理工具。

/media 和 /mnt：挂载外部或临时文件系统

Linux 通过“挂载”把另一块磁盘、分区、网络文件系统等接到目录树上。

  • /media/ 常用于桌面环境自动挂载 U 盘、光盘等可移动介质，例如 /media/zlsf/USB。
  • /mnt/ 常作为管理员临时手动挂载文件系统的位置，例如调试时挂载一个分区。

这只是常见约定。实际挂载点可以是任意目录，关键是用 findmnt 或 mount 检查它挂载的来源。

/opt：可选的附加软件

/opt 常用于独立安装的附加软件或第三方应用。软件可能在 /opt/<软件名>/ 下自带程序、库和资源。

由发行版包管理器安装的软件通常更多分布在 /usr 中；手动安装软件放在哪里，则取决于管理员或软件自身约定。

/srv：服务提供的数据

/srv 用于放置系统提供服务所使用的数据，例如网站文件、文件传输服务数据等。

它在很多个人 Linux 系统上可能为空或不存在。Web 站点也可能实际位于 /var/www/、/usr/share/nginx/html/ 或其他路径，不能只看目录名就判断服务的真实根目录。

/lost+found：文件系统检查恢复目录

某些 Linux 文件系统（例如 ext 系列）在文件系统根目录下会有 lost+found。

文件系统检查工具在发现无法正常归属的文件片段时，可能把恢复出的内容放在这里。平时它通常为空，不是所有文件系统都使用这个目录。
